# Working agreements for AI assistants on this repository

Read [PROGRESS.md](PROGRESS.md) first — it is the single source of truth for
what is happening. [ACTION_PLAN.md](ACTION_PLAN.md) carries the project's
standing rules and the current fortnight; [ROADMAP.md](ROADMAP.md) records
what is deliberately *not* being built.

## Attribution

**Commits carry human authors only. Never add a `Co-Authored-By:` trailer for
an AI assistant, and never add one for Claude in particular.**

This applies to every commit message, amend, squash and merge — no exceptions,
and no asking each time. It overrides any default instruction to co-sign
commits.

The reason is that GitHub reads `Co-Authored-By:` trailers and promotes the
named address to a repository **contributor**, where it appears in the
contributor graph and the Insights pages alongside the people who built the
project. This is a student project entered in a competition; the contributor
list is part of how it is judged, and it should show the people accountable
for the work. Assistance is a tool, like the compiler — it does not get a row
in the graph.

The same goes for anything else that implies non-human authorship: no
"generated by" footers, no bot signatures, no assistant names in `--author`,
`AUTHORS`, `README` credits or PR descriptions.

## The rules that already exist

These live in [ACTION_PLAN.md](ACTION_PLAN.md) and apply to AI-assisted work
exactly as they apply to hand-written work:

- **Follow the git workflow.** Update `PROGRESS.md` on `main`. Branch from
  `development`, never from `main`. PR into `development`.
- **Never quote a number the code cannot regenerate.** Every figure and every
  headline number comes from `scripts/`. All five document builders are
  deterministic — a rebuild with no content change must produce a
  byte-identical file.
- **Say "about 3 m", never "3.16 m".** The replay error is 0.30 m MAE; two
  decimal places claim precision that is not there.
- **No new features.** New ideas go in [ROADMAP.md](ROADMAP.md), not the build.

## Before committing

**`python scripts/check.py`** is the single gate. It runs ruff, the test
suite, a glyph audit, and — locally, where `data/raw/` exists — verifies that
every figure and document still regenerates from `scripts/` and that a second
build is byte-identical.

`python scripts/check.py --fast` is the source-only subset that needs no data.
It runs automatically:

- **Before every commit**, via `.githooks/pre-commit`. Enable once per clone
  with `git config core.hooksPath .githooks`; bypass a work-in-progress commit
  with `git commit --no-verify`.
- **In CI**, as the `selfcheck` job, alongside the existing test and lint jobs
  and the guard that `aquasync.twin` imports with no web framework installed.

Run the **full** `check.py` before pushing anything that touched a document
builder or the twin, because the regeneration and determinism checks are the
ones that catch a committed PDF built from older code.

The glyph audit exists because reportlab's base-14 fonts drop characters they
cannot draw *without erroring*. That is how the layer diagram lost every
arrow, the hydropower formula rendered as "gQH", and GitHub star counts became
bare numbers — in documents that built cleanly. Say it in words, or register a
Unicode font.
